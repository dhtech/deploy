The deploy flow

An operator runs deploy-vm <fqdn> <provisioner>. The provisioner creates the VM on the deployment VLAN, where it PXE-boots and installs Debian unattended (root and admin passwords go to the secret store). When the installer finishes, the machine is moved to its production VLAN, boots from disk, auto-enrolls in puppet and converges to its role.

Current installs — states

Starting installation
The machine has registered but the installer has not produced any log output yet (PXE/iPXE stage).
Installing
Debian installer running; the latest syslog line from the machine is shown live below the state.
Waiting for provision
Install finished; waiting for the provisioner to move the machine to its production VLAN.
Done
Moved to production. The machine is booting its installed system; puppet takes over from here.

A red line under a state is an error reported by the provisioner — the order stays visible (with its TTL ticking down) so it can be inspected and retried.

Columns

Duration
Install time so far (live), frozen at the total once finished.
TTL
Seconds until the record expires from the state store. Records are short-lived by design: roughly one hour after the last update, finished or abandoned entries clean themselves up.

Sections

Install orders
Orders waiting to be picked up by a provisioner. Virtual machine orders disappear once the VM is created; an order that lingers with an error means no provisioner could complete it.
Known VMs
All VMs each provisioner currently sees on its hypervisor — the inventory used to identify PXE-booting machines.
Hardware bays
Physical bays/nodes reported by hardware managers (blade chassis, OCP), with serials used for install matching.

Hosts-file entries

The public DNS zone already points these names at 127.0.0.1, but local entries make them work offline too. Append to /etc/hosts (sudo nano /etc/hosts — Windows: C:\Windows\System32\drivers\etc\hosts):

# dh lab web services
127.0.0.1 vault.dh.notproduction.net pve1.dh.notproduction.net pve2.dh.notproduction.net fusion.dh.notproduction.net doc.dh.notproduction.net deploy.dh.notproduction.net

Machine names

Machines (*.colo.notproduction.net) resolve only inside the lab and use the puppet CA (Puppet CA: puppet1.colo.notproduction.net). Import puppet1:/etc/puppet/puppetserver/ca/ca_crt.pem into the browser to trust the OpenBao :8200 listener.
